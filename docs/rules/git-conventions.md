# Git 運用ルール

チームでの開発をスムーズに進めるため、ブランチの命名規則とコミットメッセージの書き方を以下の通り統一します。

## 1. ブランチ命名規則

Issueに対応する作業を行う際は、以下のフォーマットでブランチを作成してください。

**フォーマット**
`prefix/Issue番号_簡単な英語の説明`

**Prefixの種類**
- `feat` : 新機能の追加、新しい画面の作成
- `fix` : バグ修正、不具合対応
- `chore` : ビルドツールやライブラリの追加・更新、設定ファイルの変更
- `docs` : ドキュメントの追加・修正
- `refactor`: 機能追加やバグ修正を含まない、コードの構造やリファクタリング

**命名例**
- ⭕️ `feat/1_setup_firebase` (Issue #1: Firebase環境構築)
- ⭕️ `feat/2_create_passion_ui` (Issue #2: 偏愛登録UIの実装)
- ⭕️ `fix/15_qr_read_error` (Issue #15: QR読み取りエラーの修正)
- ⭕️ `chore/3_add_tailwind` (Issue #3: Tailwind CSSの導入)

**NG例**
- ❌ `feature1` (Issue番号や内容がわからない)
- ❌ `fix/bug` (何のバグかわからない)

## 2. コミットメッセージ規則

コミットメッセージは、後から履歴を見たときに「何のための変更か」がすぐに分かるように、以下のフォーマット（Conventional Commitsに準拠）で記述してください。

**フォーマット**
`prefix: 変更内容の要約（日本語でOK）`
※ `prefix` と `:` の後は半角スペースを1つ空けてください。

**Prefixの種類**
ブランチ名と同様の Prefix を使用します。
- `feat:` 新機能
- `fix:` バグ修正
- `chore:` 雑務（設定変更、ライブラリ追加など）
- `docs:` ドキュメント修正
- `refactor:` リファクタリング
- `style:` コードのフォーマット修正（インデントのみの変更など、処理に影響しないもの）

**記述例**
- ⭕️ `feat: 偏愛入力用のフォームコンポーネントを作成`
- ⭕️ `fix: 卵のQRコードが生成されない不具合を修正`
- ⭕️ `chore: react-qr-code ライブラリを追加`
- ⭕️ `docs: Git運用ルールを追記`

**NG例**
- ❌ `feat:更新` (何を追加したのかわからない)
- ❌ `バグ直した` (フォーマットに従っていない)
- ❌ `fix:QR修正` (コロンの後の半角スペースがない)

---

## 💡 開発の流れ（おさらい）

1. GitHub上で対応するIssueを確認する（または作成する）
2. ローカルで `main` ブランチを最新にする (`git pull origin main`)
3. ルールに従って新しいブランチを作成する (`git checkout -b feat/X_xxx`)
4. コードを書き、ルールに従ってコミットする (`git commit -m "feat: xxx"`)
5. GitHubにプッシュし、Pull Requestを作成する
6. PRの本文には `Close #Issue番号` を記載し、マージ時にIssueが自動で閉じるようにする
